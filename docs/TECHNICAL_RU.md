# HoI4 Mod Navigator v2.1 — предварительная сборка

Windows 10/11 x64. Один скачиваемый EXE содержит собственный нативный x64 COM DLL. После применения настроек EXE и DLL размещаются в `%LOCALAPPDATA%\HoI4ModNavigator`. Настройки v1.x читаются без повторного выбора папок. Права администратора не нужны при обычном пользовательском режиме Explorer.

## Обновление и проверка

1. Запустите новый EXE из распакованного архива. Сохраните старый EXE на случай диагностики. Проверьте список модов и папку оригинальной игры.
2. Оставьте «Совместимый режим (старое меню без DLL)» выключенным. Нажмите «Применить настройки». При необходимости перезапустите «Проводник» в Диспетчере задач, предварительно завершив копирование файлов и сохранив работу.
3. ПКМ на пустом месте ванильной папки: «Открыть идентичную папку в «FFU2»» (по одной команде на мод). В FFU2: «Открыть оригинальную папку из «FFU2»». В посторонних папках команд быть не должно.
4. ПКМ на выбранном файле или папке: команды только для подходящего источника. Множественный выбор намеренно не поддерживается. На Windows 11 используйте «Показать дополнительные параметры», т.к. это классический IContextMenu, не современное пакетное меню.
5. Проверьте новое окно, обратное выделение файла, копирование с подтверждением перезаписи и отсутствие соответствующего оригинала. Динамическое меню не использует AppliesTo; галочка фильтра относится только к совместимому режиму.

## Откат и удаление

Включите совместимый режим в v2.1 и примените настройки; динамические CLSID и ContextMenuHandlers удаляются, возвращаются статические команды v1.5.1. Не запускайте старую версию для отката без удаления v2-интеграции. При необходимости перезапустите Explorer. Если настройки не открываются, запустите `remove_integration.cmd` (обычный пользователь); он удаляет только собственные записи реестра. Затем можно запустить старый EXE. «Удалить интеграцию» в GUI делает то же. DLL может оставаться загруженной до перезапуска Explorer; не пытайтесь принудительно удалить занятую DLL. Настройки и файлы игры не удаляются.

## Архитектура

- `native/shell.c`: нативный IClassFactory, IShellExtInit, IContextMenu. Три CLSID для фона, выбранной папки и файла. Данные берутся из PIDL фона или CF_HDROP выбранного одиночного объекта. Снимок настроек читается из ограниченного значения HKCU; сравнение путей без учёта регистра и с проверкой границы каталога. Вне настроенных корней и стандартного каталога локальных модов — пустое меню. Для локального каталога DLL проверяет границу пути и атрибуты первого дочернего каталога, явно зарегистрированные корни имеют приоритет. EXE заново вычисляет корень и проверяет пути. DLL не копирует и не изменяет файлы, а запускает установленный EXE для конкретной команды. В EXE остаётся прежняя проверка путей, настроек и reparse points.
- `dynamic.go`, `registry_windows.go`: генерация снимка, установка встроенной DLL и регистрация только в HKCU. Встроенная версия DLL имеет отдельное имя, при изменении DLL в следующей версии нужно сменить имя файла (и при необходимости CLSID), чтобы не перезаписывать загруженную DLL.
- `core.go`, `main_windows.go`, `folder_windows.go`, `gui_windows.go`: сохранены операции, современный диалог выбора и интерфейс v1.5.1.
- Динамические COM-расширения загружаются в Explorer. Ошибка в таком коде потенциально может нарушить работу Explorer; это предварительная сборка, а не подтверждённый Windows-релиз. Ограничения политики организации, разрядность или запрет неподписанных расширений могут препятствовать загрузке. Нет цифровой подписи. Сборка не требует сети.

## Локальные моды

`local_windows.go` получает реальный путь «Документы» через SHGetKnownFolderPath. В снимке меню есть правила для автоматического обратного перехода/сравнения и исключения для явных корней. Каталог Steam Workshop и внешние пути не распознаются автоматически. Автоматически распознанный мод не становится назначением записи. После обновления с v2.0 перезапустите Explorer: новая DLL имеет имя HoI4NavigatorShell_v21.dll.

## Сборка и тесты

Linux/WSL: Go 1.23+ (предпочтительна поддерживаемая версия) и Clang/LLD с Windows x64 target. Рекомендуемая команда — `bash scripts/build.sh`, которая также пересоздаёт DLL и ресурсный объект. Ручная сборка из корня проекта:

```sh
bash native/build.sh
clang --target=x86_64-pc-windows-msvc -x assembler -c resource.asm.txt -o icon_windows_amd64.syso
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags='-s -w -H windowsgui' -o HoI4ModNavigator.exe .
go test ./...
GOOS=windows GOARCH=amd64 go vet ./...
GOOS=windows GOARCH=amd64 go test -c -o windows-tests.exe
clang -std=c11 -fshort-wchar -Wall -Wextra -Werror -fsanitize=address,undefined native/test_shell.c -o /tmp/navshell-test
/tmp/navshell-test
```

На Windows выполните `windows-tests.exe` в тестовой среде. Host mock-тесты подменяют Windows API; они не проверяют ABI вызовов непосредственно Explorer. Скомпилированные Windows-тесты в этой среде не выполнялись. Фактический запуск GUI, загрузка COM, поведение Проводника и SmartScreen требуют проверки на Windows.
